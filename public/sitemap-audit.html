What this actually does (read before you rely on it)
This fetches your sitemap.xml (following sitemap index files to their sub-sitemaps automatically), extracts every <loc> URL, and runs each one through the same technical checks as the Indexability Checker: HTTP status, robots.txt rules, meta robots "noindex", the X-Robots-Tag header, redirects, and canonical tag mismatches. It does not tell you whether a page is already indexed — only whether it's technically eligible to be. URLs are checked concurrently and robots.txt is cached per host during the scan to keep things fast, but scans of several thousand URLs can still take a few minutes — keep this tab open until it finishes. Common sitemap waste patterns

Stale redirects

After a URL structure change, old URLs often stay in the sitemap pointing through a 301 redirect. Search engines index the destination, not the listed URL — so the listing itself does nothing.

Noindex leftovers

Pages marked noindex during a staging or A/B test phase sometimes never get removed from the sitemap afterward, silently wasting crawl budget indefinitely.

Robots.txt drift

A robots.txt rule added for one reason (blocking a filter parameter, for example) can accidentally match paths that are still listed in the sitemap.

Canonical conflicts

Auto-generated sitemaps sometimes list every URL variant, even ones whose canonical tag points elsewhere — meaning the sitemap entry and the page's own preference disagree.

Frequently asked questions

What is sitemap waste?

Sitemap waste refers to URLs listed in a sitemap.xml that can never actually be indexed — because they're blocked by robots.txt, carry a noindex tag, redirect elsewhere, or have a canonical tag pointing elsewhere. Submitting these URLs to search engines or spending crawl budget on them accomplishes nothing.

Why would my sitemap contain pages that can't be indexed?

This commonly happens after a site migration, a CMS plugin auto-generating the sitemap without checking robots directives, redirects being added without updating the sitemap, or noindex tags being added to pages without removing them from the sitemap afterward.

How many URLs can be audited at once?

Up to 10,000 URLs per scan, including sitemap index files that reference multiple sub-sitemaps. Very large sitemaps are processed concurrently to keep scan time reasonable, but scans of several thousand URLs can still take a few minutes.

Why does a redirect count as sitemap waste?

A redirecting URL isn't necessarily broken, but listing it in your sitemap wastes crawl budget — the destination URL is what actually gets indexed, not the one you listed. Sitemaps should generally list only final, canonical URLs.
