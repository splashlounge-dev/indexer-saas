What gets checked, and why it matters

SignalWhat it meansIf it blocks indexing
HTTP status code Whether the page loads successfully (200) or returns an error/redirect. A 4xx or 5xx status means there's no valid page to index at all.
robots.txt A file at your site's root that tells crawlers which paths they may or may not visit. A Disallow rule matching the page's path stops crawlers from even fetching it.
Meta robots tag A <meta name="robots"> tag inside the page's own HTML. A value containing noindex explicitly tells search engines to exclude the page.
X-Robots-Tag header The same kind of directive as meta robots, but sent as an HTTP response header instead. Often missed because it's invisible in the page source — it only shows up in response headers.
Canonical tag A <link rel="canonical"> tag declaring which URL is the "main" version. If it points to a different URL, search engines usually index that URL instead of this one.

Frequently asked questions

What does "indexable" mean?

A page is indexable when nothing is technically blocking a search engine from adding it to its index: it returns a successful HTTP status, robots.txt doesn't disallow it, there's no noindex meta tag or X-Robots-Tag header, and its canonical tag points to itself rather than another URL.

Does this tool tell me if my page is already indexed?

No. Checking whether a page has already been indexed requires access to a search engine's own index data, such as through Google Search Console. This tool instead checks eligibility — whether the page is technically allowed to be indexed right now, which is usually the more actionable question when a page isn't showing up in search.

What is a noindex tag and why does it block indexing?

A noindex directive — set either as a meta robots tag in the page's HTML or as an X-Robots-Tag HTTP header — explicitly tells search engines not to include that page in their index. It's often left on by accident after a site migration or staging environment goes live.

Why would a canonical tag block indexing?

A canonical tag tells search engines which URL is the "main" version of a page. If a page's canonical tag points to a different URL, search engines usually index that other URL instead and treat the current page as a duplicate, even if the content is unique.
