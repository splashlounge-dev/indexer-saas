What this actually checks (read before you rely on it)
This scans the page's HTML for <script type="application/ld+json"> blocks, parses each one as JSON, and extracts every @type value — including types nested inside @graph arrays or common properties like mainEntity and author. It reports whether the JSON itself is syntactically valid and shows the parse error if it isn't. It also does a basic check for older microdata markup (itemscope/itemtype) as a fallback signal. This does not validate against every schema.org property requirement the way Google's Rich Results Test does — it's a fast first pass to see what's there and whether it parses at all.

Why structured data matters more than ever

Rich results in Google

FAQPage, Product, Recipe, and Review schema are what let Google show star ratings, prices, and expandable FAQs directly in search results — without it, you're only eligible for a plain blue link.

AI answer engines

Tools like Google's AI Overviews and other AI-driven search rely heavily on structured data to extract facts accurately from a page. Clean, valid schema makes a page far easier for these systems to cite correctly.

Invalid JSON breaks silently

A single missing comma or unescaped quote in a JSON-LD block makes the entire block unreadable to crawlers — the schema doesn't degrade gracefully, it just gets ignored.

Nested types are easy to miss

Many pages define an outer type (like WebPage) but nest the more specific type — an FAQPage or Article — as a sub-property. This tool follows those nested references so you see the full picture.

Frequently asked questions

What is structured data and why does it matter?

Structured data is machine-readable markup (usually JSON-LD) that tells search engines and AI systems exactly what a page's content means — a recipe, a product, an FAQ, an article. It's what powers rich results in Google and is increasingly what AI-driven search and answer engines rely on to extract accurate information from a page.

Does this tool check if my structured data is valid?

Yes — it parses every JSON-LD block on the page and reports whether the JSON itself is syntactically valid, along with the specific parse error if it isn't. It does not validate against every schema.org property requirement the way Google's Rich Results Test does.

What if my page has no structured data at all?

The tool will flag the page as having no schema markup. This isn't necessarily an error — not every page needs structured data — but for pages competing for rich results or AI-generated answers, adding relevant schema (FAQPage, Article, Product, HowTo, etc.) is usually worth doing.
